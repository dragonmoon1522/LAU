## 7. Accessibility commitment

Modifications must not deliberately remove existing accessibility features without providing an alternative that allows the same essential functions to be performed accessibly.

When a modification introduces an interface or new form of interaction, reasonable efforts must be made to ensure that its essential functions remain accessible according to the characteristics and technical context of the project.

Barriers to avoid, where applicable, include:

- unnecessarily preventing use with screen readers or other assistive technologies;
- preventing keyboard navigation where the interface supports keyboard interaction;
- removing text alternatives necessary to understand non-text content;
- introducing essential controls that cannot be identified or operated through compatible assistive technologies;
- deliberately removing accessibility features present in the original Work without providing an equivalent alternative.

The existence of an accessibility bug or incompatibility does not by itself constitute a deliberate violation of this license.

Where reasonably possible, identified accessibility problems are expected to be documented and corrected.

> Accessibility is not a privilege; it is a right.
